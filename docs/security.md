# Security Model and Threat Assessment

The app runs untrusted code: code users write, code in imported files, and code produced by an LLM. It also stores user history and, optionally, an API key on the same origin. This document states what is protected, how, and what is **not** guaranteed. The decisions are recorded in [ADR-006](adr/006-code-execution-security-model.md), [ADR-015](adr/015-react-sandbox-development-build.md) and [ADR-016](adr/016-loop-guards.md).

## Assets

| Asset                           | Where                   | Sensitivity          |
| ------------------------------- | ----------------------- | -------------------- |
| Anthropic API key (optional)    | `localStorage`, own key | High                 |
| Challenge history and solutions | IndexedDB               | Medium (user's work) |
| Application integrity           | the page's JS realm     | High                 |

## Threats and mitigations

| Threat                                        | Mitigation                                                                                                                                                                                                                                                                                                                                                      | Residual risk                                                                                                                                                                                |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **User or LLM code reads storage or the key** | Code never runs in the app's realm. It runs in Workers (separate global; no DOM or localStorage) or in an opaque-origin iframe (no storage access at all). Workers also have `fetch`, `XMLHttpRequest`, `WebSocket`, `indexedDB`, `caches`, `importScripts`, `BroadcastChannel`, `Worker` and others removed after the toolchain loads.                         | Removing globals is defence in depth, not a boundary. A determined script could look for other same-origin channels from a Worker. The worker realm and termination are the actual controls. |
| **Code forges test results**                  | Host and runtime talk over a private `MessagePort` that is transferred at startup and never exposed to user code. Stdout-based harnesses tag result lines with a per-run random nonce and a control character, so printed look-alike lines are ignored (tested).                                                                                                | User code runs in the same realm as its harness and can monkey-patch it. This is accepted: the tool isn't a secure grader.                                                                   |
| **Infinite loops or CPU exhaustion**          | A wall-clock timeout terminates the Worker or removes the iframe. JS loops are instrumented with time budgets (5 s in Workers, 1 s in the iframe) because an iframe may share the page's thread.                                                                                                                                                                | A tight infinite loop in _non-loop_ JS (e.g. deep synchronous recursion) is stopped by a stack overflow, not a budget. WebAssembly loops rely on termination.                                |
| **Enormous output**                           | Output is capped at 64 KB per stream on the runtime side _before_ it crosses the channel, and again on the host side. Stored runs keep at most 8 KB.                                                                                                                                                                                                            | PHP returns output only at the end, so a runaway `echo` grows memory until the timeout kills the worker.                                                                                     |
| **WebAssembly memory exhaustion**             | A worker crash becomes an `internal-error` result, and the worker is recreated.                                                                                                                                                                                                                                                                                 | The browser may briefly use a lot of memory.                                                                                                                                                 |
| **iframe escape or navigation**               | `sandbox="allow-scripts"` only: no `allow-same-origin`, `allow-top-navigation`, `allow-popups` or `allow-forms`. The production CSP adds `connect-src 'none'; frame-src 'none'; worker-src 'none'; form-action 'none'; object-src 'none'; base-uri 'none'`. The parent accepts readiness only from `iframe.contentWindow` and communicates over a private port. | Depends on the browser's sandbox implementation.                                                                                                                                             |
| **XSS through challenge text**                | Challenge Markdown is parsed by an in-house renderer that builds React elements. Raw HTML is shown as text, and only `http(s)` links are kept, opened with `rel="noopener noreferrer nofollow"`. There is no `dangerouslySetInnerHTML` anywhere.                                                                                                                | —                                                                                                                                                                                            |
| **Malicious import files**                    | Imports are size-limited (20 MB), parsed with `JSON.parse` only, Zod-validated per attempt (invalid entries are skipped and counted), and previewed before writing. Imported code never runs automatically.                                                                                                                                                     | An imported challenge's code runs when the user presses Run or Test, which is the same sandbox as any code.                                                                                  |
| **Hostile LLM output**                        | Schema validation with size limits on every string. Static language rules reject disallowed imports and APIs. The reference solution runs in the sandbox before the challenge is accepted.                                                                                                                                                                      | A challenge can still be wrong in subtle ways that its tests don't catch.                                                                                                                    |
| **Corrupt local storage**                     | Every IndexedDB record is validated on read. Invalid records are left in place and reported, never crashing the app. Settings are validated field by field.                                                                                                                                                                                                     | —                                                                                                                                                                                            |
| **API key exposure**                          | The key is entered only after an explicit warning. It's stored under its own `localStorage` key, excluded from the settings schema (so it can't be exported), never logged, masked in the UI, and sent only to `api.anthropic.com` with the documented browser-access header.                                                                                   | Any script running on this origin, and anyone with access to the browser profile, can read it. The optional proxy mode avoids keys in the browser.                                           |
| **Dependency vulnerabilities**                | Few runtime dependencies, each justified in an ADR. CI runs `npm audit --omit=dev --audit-level=high`. Toolchains are pinned to exact versions and served from versioned paths.                                                                                                                                                                                 | `@yowasp/clang`'s repository is archived: it's a frozen, pinned build.                                                                                                                       |

## Explicit non-guarantees

- **Hidden tests and reference solutions are not secret.** They ship to the browser and are visible in devtools and in IndexedDB.
- **Test results can be manipulated** by the person running the code. Portfolio results show what the author did, not a proctored outcome.
- **An API key is only as safe as the browser** it's stored in.
